# Lease signing contract (lease-v1)

Status: P2 groundwork — the cross-language encoding contract between the
Rails issuer and the Rust agent verifier. Executed evidence 2026-09-07.
Key ceremony, distribution, and rotation remain owner ADR decisions
(oma-id_plan.md §5.3 — lease-signing keys are a separate key purpose).

## Payload schema

Identical to `oma-id-agent-store::LeasePayload`:

| Field | Type | Notes |
|---|---|---|
| `subject_id` | string | immutable directory identity |
| `device_id` | string | enrollment generation binding |
| `not_before` | u64 | unix seconds |
| `expires_at` | u64 | unix seconds |
| `revocation_epoch` | u64 | monotonic, never decreasing |
| `operations` | string[] | `Login` / `Unlock` / `Elevate` / `RemoteLogin`, issuer-supplied order |

## Canonical encoding (byte-exact)

Compact JSON, fields in exactly this order, no whitespace:

```
{"subject_id":"…","device_id":"…","not_before":N,"expires_at":N,"revocation_epoch":N,"operations":["Login","Unlock"]}
```

- Field order is schema-pinned, not sorted-by-key.
- Strings use minimal JSON escaping (quote, backslash, control chars as
  `\u00XX`); both encoders escape identically.
- Integers are plain decimal, no signs, no leading zeros.
- `operations` preserves issuer order (the agent authorizes whatever the
  issuer granted; ordering is part of the signed bytes).
- Any other byte sequence produces a different signature **by design**.

Both sides have drift tests: the Rust suite compares its encoder against
serde and against the exact pinned string; the Rails suite compares its
encoder against the same pinned string.

## Signature

- Algorithm: Ed25519 (PureEdDSA over the canonical bytes).
- Agent: `ed25519-dalek` 2, `verify_strict` against a pinned 32-byte issuer
  key (hex-encoded in the store CLI argument).
- Rails: `ed25519` gem 1.4. Lab key: fixed seed for fixtures/experiments
  only (`OMA_ID_ISSUER_SEED`); production keys need the ADR.
- Signatures are hex-encoded (64 bytes → 128 hex chars).

## Cross-language fixture

`protocol/lease-v1/rails-signs-vector.json` is generated by the Rails suite
(`server/test` fixture generator below) from a fixed seed + payload. The
Rust test `oma-id-agent-store/tests/rails_vector.rs` verifies it on every
CI run — encoder or schema drift between the languages fails loudly.

Regenerating: `cd server && bin/rails runner scripts/generate-lease-vector.rb`
(writes the file; the Rust test must stay green afterwards).

## Rails entry point

`OmaId::LeaseSigningKey` (`server/app/services/oma_id/lease_signing_key.rb`):
`from_seed_hex`, `canonical_payload_json(payload)` (module function),
`sign(payload)` → hex, `verify(payload, hex)` → bool, `verify_key_hex`.
Payload validation raises before any signing: unknown operations, empty
operations, negative/non-integer times.
